The API behind three mobile apps

Technicians, customers and stock-count staff each have their own app. All three talk to the same backend, and that backend is mine to specify, build and keep fast.

Problem
Three mobile apps needed dependable, documented APIs, and some screens slowed down on very large tables.
What I built
The REST APIs for all three apps, specified and documented before build, then released to production with the mobile team.
Outcome
Faster screens, fewer round trips, cleaner vehicle data and an API the mobile team can build against without guessing.

Context

The apps cover daily work in the workshop: technicians logging time and work, customers following their vehicle, and staff counting stock. They all sit on the same SQL Server databases, some of which are very large.

The problem

  • Each app needed clear APIs for time tracking, work logs and vehicle inspections.
  • Some screens needed several calls to load, and large tables made a few screens and the login slow.
  • Vehicle master data had invalid entries that caused problems further down the line.

What I did

  • Specified, built and documented the REST APIs for the technician, customer and stock-count apps.
  • Merged the job-tracking calls into a single endpoint.
  • Traced and fixed the slow stock-count screens and the slow login.
  • Added validation for vehicle records.
  • Worked with the mobile team on releases, from test builds to production.

How I approached it

  • Write the contract first. Each API is specified and documented before it is built, so mobile and backend work can run in parallel.
  • One screen, one call. Screens that needed several requests get one endpoint shaped for them.
  • Fix the cause. Slow screens were traced to the queries and data behind them, not papered over in the app.
  • Keep logic close to the data. Business queries run as SQL Server stored procedures.

How it fits together

Where it landed

  • Stock-count and login performance problems resolved.
  • Job tracking is served by one endpoint instead of several.
  • Vehicle records are validated before they are saved.
  • Every API is documented for the mobile team.

Built with C#, ASP.NET Web API, REST, SQL Server, stored procedures

Written at the level of what the system does. No company code, data, screenshots or internal details.
